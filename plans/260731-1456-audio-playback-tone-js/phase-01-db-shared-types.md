# Phase 01: DB Schema + Shared Types

## Context Links
- Schema: `packages/db/src/schema/notes.ts`
- Shared types: `packages/shared/src/types.ts`
- Shared constants: `packages/shared/src/constants.ts`
- Shared socket events: `packages/shared/src/socket-events.ts`

## Overview
- **Priority:** P1 (blocks all other phases)
- **Status:** pending
- **Description:** Add `pitch`, `duration`, `velocity` columns to the `notes` table with CHECK constraints. Extend shared Note type, constants, and socket payloads. Generate + run Drizzle migration.

## Key Insights
- Current `title` field holds free-text like "Note" -- NOT a pitch identifier. We ADD `pitch` alongside `title`, not replace it.
- UNIQUE(song_id, track, time_tick) stays valid: each grid cell is still unique by start position. Duration is rendering metadata, not a key change. Overlap detection (two notes on same track overlapping in time) is deferred -- YAGNI for V1.
- Service layer uses spread (`{ ...input, songId }`) so new fields flow through automatically once schema + validator are extended.
- `toNoteDto` in `apps/api/src/lib/to-note-dto.ts` must map new fields.

## Requirements
**Functional:**
- `pitch` column: integer, MIDI note 0-127, NOT NULL, default 60 (C4)
- `duration` column: integer, ticks >= 1, NOT NULL, default 1 (0.25s)
- `velocity` column: integer, 1-127, NOT NULL, default 100
- Backfill all existing rows with defaults on migration
- Extend `Note` interface in shared with `pitch`, `duration`, `velocity`
- Add constants: `DEFAULT_PITCH = 60`, `DEFAULT_DURATION = 1`, `DEFAULT_VELOCITY = 100`, `MIN_VELOCITY = 1`, `MAX_VELOCITY = 127`, `MAX_PITCH = 127`
- Extend socket payloads `NoteCreatePayload` and `NoteUpdatePayload` with optional pitch/duration/velocity

**Non-functional:**
- Migration must be backward-compatible (defaults on new columns)
- No downtime: additive schema change only

## Architecture

## Implementation Steps

1. **Add columns to `packages/db/src/schema/notes.ts`:**
   ```ts
   pitch: integer("pitch").notNull().default(60),
   duration: integer("duration").notNull().default(1),
   velocity: integer("velocity").notNull().default(100),
   ```
   Add CHECK constraints in the table config callback:
   ```ts
   check("chk_notes_pitch", sql`${t.pitch} BETWEEN 0 AND 127`),
   check("chk_notes_duration", sql`${t.duration} >= 1`),
   check("chk_notes_velocity", sql`${t.velocity} BETWEEN 1 AND 127`),
   ```

2. **Extend `packages/shared/src/constants.ts`:**
   ```ts
   export const DEFAULT_PITCH = 60 as const;
   export const MAX_PITCH = 127 as const;
   export const DEFAULT_DURATION = 1 as const;
   export const DEFAULT_VELOCITY = 100 as const;
   export const MIN_VELOCITY = 1 as const;
   export const MAX_VELOCITY = 127 as const;
   ```

3. **Extend `packages/shared/src/types.ts` Note interface:**
   ```ts
   /** MIDI pitch number 0-127 (60 = C4) */
   pitch: number;
   /** Duration in ticks (>= 1) */
   duration: number;
   /** Velocity / loudness 1-127 */
   velocity: number;
   ```

4. **Extend `packages/shared/src/socket-events.ts`:**
   - `NoteCreatePayload`: add optional `pitch?: number`, `duration?: number`, `velocity?: number`
   - `NoteUpdatePayload`: add optional `pitch?: number`, `duration?: number`, `velocity?: number`

5. **Update `apps/api/src/lib/to-note-dto.ts`:**
   Add `pitch`, `duration`, `velocity` to the returned object.

6. **Generate migration:**
   ```bash
   cd packages/db && pnpm db:generate
   ```

7. **Run migration:**
   ```bash
   cd packages/db && pnpm db:migrate
   ```
